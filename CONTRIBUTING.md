# Участие в комплекте

Спасибо за желание помочь. Небольшие исправления — сразу pull request из своего fork;
новый пункт комплекта или изменение подхода — сначала issue, чтобы обсудить.

## Что проверить перед pull request

Скрипты гоняются из клона репозитория; нужны Node.js 22.19+, npm, bb 0.46+ и сеть
(registry.npmjs.org, cdn.sheetjs.com):

```sh
scripts/test-plugins.sh                      # typecheck, bb plugin build, тесты пяти плагинов
python3 scripts/build-kit.py                 # собрать выпуск в release/
python3 scripts/check-kit.py                 # проверить выпуск: ZIP, манифест, файл для агента
```

`test-plugins.sh` собирает плагины в копии и ничего не меняет в репозитории.
`build-kit.py` перезаписывает `MANIFEST.json` и `release/` — не включайте эти изменения
в pull request, актуальные манифест и архив собираются заново при выпуске. Если правили
только документы, достаточно `build-kit.py` + `check-kit.py` и беглой проверки ссылок.

Pull request проходит CI: тот же цикл по плагинам на Linux и Windows, сборка и проверка
комплекта. Красная CI-строка с логом — самый быстрый способ понять, что упало.

## Приватность

Личные пути, токены, имена клиентов и закрытых репозиториев в изменения не включайте.
Перед отправкой можно прогнать поиск личного — тот же, что в выпуске:

```sh
python3 scripts/check-kit.py --private-patterns ПУТЬ/К/ФАЙЛУ
```

Файл с шаблонами храните вне репозитория: по одной регулярке на строку.

## Соглашения репозитория

- Тексты — по-русски; стиль и тон — как в `README.md` и `GUIDE.md`.
- У трёх своих плагинов версия в `package.json` равна версии комплекта и поднимается
  только при выпуске; у `files-editor` и `floating-terminal` версии продолжают счёт
  авторов оригиналов. Версии зависимостей и `package-lock.json` не меняйте без нужды.
- `MANIFEST.json` и `catalog.json` собираются `scripts/build-kit.py`; руками правьте
  только метаданные, которые он не трогает (состав разделов, тексты).
- Плагины переносятся из рабочего репозитория автора скриптом `scripts/sync-plugins.py`;
  правки прямо в `plugins/` могут затереться при следующем переносе — сначала обсудите
  в issue.
